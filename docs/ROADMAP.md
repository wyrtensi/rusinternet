# RusInternet roadmap

Актуально на 30 августа 2026 года.

## Обновление 28 августа 2026 (дизайн + ревью скриптов)

- [x] Компактный дизайн главной: сжатый вертикальный ритм (меньше прокрутки), умеренно закруглённые углы через токены `--radius/-sm/-xs`, более спокойные тени.
- [x] Переработанная зона поддержки: карточка доната с QR и ссылкой Ozon, партнёрские баннеры (data-driven, легко добавить) и раскрываемый слот «Разместить свой баннер».
- [x] Улучшенная инструкция для Android: честное объяснение защиты, отметка обязательных корней, заметка про уведомление «Сеть может отслеживаться».
- [x] Усиление установщиков (S1–S5): проброс кода возврата и видимый провал на Windows, устранён TOCTOU при elevation, безопасный субшелл и явные ошибки в команде macOS/Linux, корректный выбор хранилища на Arch/SUSE, идемпотентность macOS.
- [x] 35 автоматических проверок (был 33): добавлены негативный тест подмены сертификата и проверка ветки ошибки в команде установки.
- [x] SEO под реальные запросы: заголовки/описания и главная переориентированы на боль пользователя («не защищено», ошибка сертификата на Госуслугах, в банках, на маркетплейсах); секция «Кому помогает» с примерами ошибок (ERR_CERT_AUTHORITY_INVALID, SEC_ERROR_UNKNOWN_ISSUER); расширенный FAQ + FAQPage JSON-LD; lastmod в sitemap, og:site_name. Без doorway-страниц и скрытого текста.

## Публикация

- [x] Деплой на GitHub Pages из `main`: workflow тестирует, собирает и публикует `dist/`.
- [x] Собственный домен через `public/CNAME`; HTTPS выпускается автоматически (Let's Encrypt) — сайт с корневыми сертификатами обязан отдаваться только по HTTPS.
- [x] GitHub Pages Enforce HTTPS включён; сертификат для `rusinternet.com` и `www.rusinternet.com` одобрен, HTTP-редиректы активированы.
- [x] На production проверена доступность `.cer`, `.cmd`, `.sh`, `manifest.json`, RU/EN-страниц и внутренних ссылок.
- [ ] Проверить установку `.mobileconfig` на реальном iPhone/iPad: GitHub Pages отдаёт файл как `application/octet-stream`, а не `application/x-apple-aspen-config`.
- [ ] Подключить Яндекс.Вебмастер, Google Search Console и Bing; отправить sitemap.

## Готово

- [x] Нейтральный адаптивный интерфейс, автоопределение ОС, ручной выбор платформы, светлая/тёмная тема.
- [x] Русская главная и полноценная английская главная.
- [x] Один основной сценарий установки без отдельной кнопки сырых сертификатов на главной.
- [x] Пять распакованных сертификатов, публичный manifest и проверка SHA-256.
- [x] Windows: CMD-установщик, UAC, отдельные Root/CA-хранилища, проверка после импорта, абсолютные пути системных утилит.
- [x] macOS: одна команда с проверкой хэша установщика; корни и intermediates импортируются с разной семантикой.
- [x] Linux: одна команда, распознавание PEM/DER и установка только двух корней как trust anchors; три intermediates проверяются, но не повышаются до корней.
- [x] iOS/iPadOS: профиль из пяти сертификатов и системные шаги включения доверия.
- [x] Android: честный guided flow; автоматическая установка CA не обещается из-за ограничения Android 11+.
- [x] FAQ, ограничения, QR-пожертвование, партнёр wyrtensi, раскрываемый контакт.
- [x] SEO-база: canonical, RU/EN hreflang только для настоящих переводов, sitemap, robots, JSON-LD, Open Graph.
- [x] `security.txt`, конфигурация MIME/security headers для Apache-совместимого зеркала и отсутствие листинга каталогов на production.
- [x] 36 автоматических проверок: платформы, allowlist, сертификаты, установщики, manifest и workflow.
- [x] Визуальная проверка desktop/mobile, двух тем и интерактивных блоков.
- [x] GitHub Actions: build/test и публикация проверенной сборки из `main` на GitHub Pages.
- [x] GitHub Actions verification-run на Ubuntu: `npm ci`, тесты и production-сборка проходят.

## Не делать

- Не скрывать поисковые фразы и не создавать doorway-страницы.
- Не обходить системные подтверждения установки CA.
- Не добавлять intermediates Linux в trust anchors.
- Не менять Firefox enterprise policy, если он уже существует.
- Не публиковать сертификаты или установщики при несовпадении SHA-256.
