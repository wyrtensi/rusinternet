# Безопасность установщиков

## Модель доверия

Сайт распространяет ровно пять заранее известных сертификатов: два корневых и три промежуточных. Идентичность фиксируется SHA-256 в `public/downloads/manifest.json`; release-хэши установщиков находятся в `src/lib/release.ts` и проверяются тестами.

## Защиты

- Любое несовпадение хэша останавливает установку до изменения trust store.
- Windows разделяет Root и CA, использует UAC и абсолютные пути `%SystemRoot%\System32`.
- macOS назначает `trustRoot` только корням; intermediates импортируются без повышения до root.
- Linux добавляет в anchors только два корня.
- iOS использует профиль, но оставляет системные подтверждения пользователю.
- Android оставляет импорт пользователю, потому что ОС запрещает silent CA install.
- В Git release-файлы хранятся как байтовые артефакты без EOL-преобразований.
- GitHub Actions использует `contents: read`, отдельные `pages: write`/`id-token: write` для Pages OIDC и immutable SHA для используемых actions; долгоживущие deploy-пароли workflow не нужны.

## Транспорт и заголовки production

- Для GitHub Pages включён **Enforce HTTPS**; сертификат охватывает `rusinternet.com` и `www.rusinternet.com`.
- HTTP не должен использоваться для раздачи установщиков или контрольных сумм: незашифрованную страницу и сам установщик можно подменить одновременно.
- Строгая CSP доставляется ранним HTML `<meta>` и действует на текущем production: `default-src 'none'`, исполняемые скрипты и стили разрешены только с того же origin, inline event/style-атрибуты запрещены, JSON-LD разрешён только по точным SHA-256-хэшам. `npm run build` проверяет итоговые страницы на регрессии политики.
- GitHub Pages не исполняет `public/.htaccess`. Файл остаётся конфигурацией Apache-совместимого зеркала, но его response headers и MIME-настройки не действуют на текущем production.
- Произвольные HSTS и Permissions-Policy недоступны. Meta CSP также не поддерживает `frame-ancestors`, reporting и другие header-only-возможности; для них потребуется управляемый CDN/proxy или другой hosting.
- На production `.cer` отдаётся как `application/pkix-cert`, shell-скрипты — как `application/x-sh`, manifest — как JSON. `.mobileconfig` отдаётся как `application/octet-stream`, поэтому его установка должна быть подтверждена на реальном iOS/iPadOS.

## Результат внешнего ревью

Ревью от 27–28 августа 2026 года не нашло Critical-проблем. До публикации были исправлены четыре Important-проблемы:

1. Сравнение uppercase/lowercase хэша, которое блокировало macOS/Linux command.
2. Ошибочное предположение, что все Linux-файлы DER (часть файлов — PEM).
3. Bare-вызовы `powershell.exe`/`certutil.exe` после UAC и риск binary planting.
4. Повышение intermediates до Linux trust anchors.

Также исправлены homepage fragments на guide pages, `aria-pressed` выбора ОС и неверные hreflang на непереведённых инструкциях.

## Второе ревью установщиков (28 августа 2026)

Повторный аудит подтвердил: ни один путь не устанавливает сертификат без совпадения закреплённого SHA-256, инъекций в логику проверки нет. Исправлены проблемы видимости и границ доверия — без ослабления модели:

1. **Windows, невидимый провал и exit 0.** `exit /b %errorlevel%` внутри блока `(...)` раскрывался на этапе разбора и всегда давал 0; `Start-Process -Verb RunAs` не ждал дочерний процесс. Теперь elevation вынесена в метку, используется `-PassThru -Wait; exit $p.ExitCode`, код возврата пробрасывается пользователю, а elevated-окно остаётся открытым (`pause`) до прочтения результата.
2. **Windows, TOCTOU при elevation.** Проверенные файлы лежали в `%TEMP%` пользователя (доступен на запись из non-admin процессов) в окне между проверкой и `certutil`. В elevated-режиме рабочий каталог перенесён в `%SystemRoot%\Temp` (запись только для администраторов).
3. **Команда установки (macOS/Linux) молча ничего не делала при несовпадении.** Теперь команда выполняется в субшелле `( … )`: `exit` не закрывает терминал пользователя, trap и переменные не протекают в сессию, а при ошибке скачивания или несовпадении хэша печатается явная причина. Добавлены `--proto '=https' --proto-redir '=https'`.
4. **Linux, ложный успех на Arch.** Хранилище теперь выбирается по фактически существующему каталогу anchors (RHEL/Fedora, Arch, Debian/Ubuntu, openSUSE), а корни кладутся плоскими файлами с префиксом `rusinternet-`. Промежуточные по-прежнему не становятся anchors.
5. **macOS, не идемпотентно.** Повторный запуск падал на `security import` уже существующего сертификата. Импорт обёрнут: «уже существует» трактуется как успех; бессмысленный флаг `-T /usr/bin/security` убран.

Добавлен негативный тест: при подмене байта в сертификате установщик завершается ненулевым кодом и не печатает `CERTIFICATES_VERIFIED=5`. Байтовые изменения скриптов синхронно обновляют `src/lib/release.ts` и `public/downloads/manifest.json` (проверяется тестами).

## Ограничения

Установка root CA расширяет круг доверия всей системы. Проект не обещает обход блокировок, не меняет DNS и не добавляет поддержку ГОСТ-шифрования браузеру. Реальные platform smoke-tests остаются обязательными перед широким анонсом.
